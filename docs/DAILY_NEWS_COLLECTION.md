# Daily research news collection

GitHub Actions fetches and encrypts NewsAPI research responses while the desktop
is off. Sentiment scoring, deduplication, feature generation and model work stay
local. No trading or model-training step runs here.

## Scope and limits

- Workflow: `.github/workflows/daily-newsapi.yml`.
- Daily opportunities: **20:17 UTC** and **23:47 UTC**, including weekends.
  Both share one persisted budget and concurrency group.
- Fixed query: `stock market OR equities OR earnings`, English, sorted by publication time.
- Only news at least **24 hours and 15 minutes old**, rounded down to an hour.
- Each fixed one-hour window requests **one page of at most 100 articles**.
  There is no paid-page pagination, query switching or adaptive window splitting.
- The initial explicit bootstrap covers **48 hours ending at that delayed cutoff**;
  it does not claim to recover the entire historical archive.
- Maximum **80 requests per rolling 24 hours** from this workflow, including
  recovery attempts. This leaves 20 of the Developer plan's stated daily 100
  for other callers; other clients must respect that shared account allowance.
- Retry incomplete windows at most three times, at least six hours apart.
  Three consecutive transport failures stop a run. Manual `probe=true` may
  bypass the time backoff for just one request; quota and attempt limits remain.
  Current newly reachable windows take priority. Gaps older than 28 days are
  counted as expired; they are never silently called complete.
- Truncated, failed, invalid and exhausted-retry windows remain unresolved.
  The run reports a failure after securely archiving its audit when gaps remain.
  A passing run verifies only requested-window consistency, not exhaustive
  publisher coverage or future late-indexed additions to completed windows.

The [NewsAPI Developer plan](https://newsapi.org/pricing) is limited to development
and testing, has a 24-hour delay, and is not licensed for production use. This
collector is for research archiving; deploying it does not change those terms.
The API itself supplies truncated article content, not full publisher articles.

## Private data in a public code repository

The provider key is the repository Actions secret `NEWSAPI_KEY`. It is sent only
as an HTTPS request header. Provider response bodies, article data and detailed
coverage audits are never printed in public logs or committed to Git.

Responses and state use gzip plus authenticated Fernet encryption. The separate
Actions secret `NEWS_ARCHIVE_KEY` is generated by the local setup helper. Only
encrypted `batch.enc` and `state.enc` files are uploaded as artifacts. Run timing,
success/failure and ciphertext sizes remain visible in this public repository.

The Windows helper retains the archive key in a user-scoped DPAPI file outside
Git. It neither reads nor uploads your local NewsAPI key. Do not delete this file:
GitHub secrets cannot be downloaded, and encrypted artifacts cannot be decrypted
without the original key. DPAPI recovery depends on your Windows user profile;
copying the blob alone is not a portable recovery backup. Retain a suitable
protected Windows-profile/system backup. Never post either key in an issue or chat.

## Setup and manual checks

1. Add `NEWSAPI_KEY` through repository Settings → Secrets and variables → Actions.
2. On the Windows archive machine, install `automation/requirements.txt` and
   authenticate GitHub CLI for this repository, then run:

   ```powershell
   python -B automation/local_archive.py setup-key --key-file private/archive_key.dpapi
   ```

   Retain that exact file. Setup reuses it on retries and refuses to replace a
   remotely configured archive key when the original local file is missing.
3. Run the workflow with `dry_run=true`. Offline tests make no provider requests.
4. For the first collection only, run `dry_run=false`, `bootstrap=true`.
5. Later manual runs use `dry_run=false`, `bootstrap=false`; schedules use saved state.

Quota is reserved in a durable encrypted state artifact **before** API calls.
The batch is uploaded **before** the final state advances completed windows.
An interrupted worker therefore retains a conservative request reservation.
Missing or expired latest state fails closed; it never silently resets the quota.

## Download and process locally

Run this regularly on the Windows user profile that created the archive key:

```powershell
python -B automation/local_archive.py download --key-file private/archive_key.dpapi --out private/downloaded
```

Each artifact gets a directory with `batch.enc`, decrypted `batch.json` and a
last-written `receipt.json`. Repeated downloads skip receipted artifacts.
The downloader does not call NewsAPI or change the project's NLP store.
Keep the decrypted output in a private, Git-ignored directory.

The JSON contains each requested interval, original API response, actual
`fetched_at`, completeness status and outstanding-window count. Local processors
must deduplicate by source/URL, preserve the earliest actual cloud observation
time, and distinguish `publishedAt` from `fetched_at`. Do not backdate an article's
availability to publication time in historical sentiment tests.

Artifacts expire after **90 days**. Download before expiry; this is a temporary
cloud buffer, not a permanent cloud archive. The collector blocks when this
repository's nonexpired artifacts exceed 400 MB. GitHub storage is shared with
other repositories, so that check alone cannot enforce an account-wide quota.
No artifact is automatically deleted by this collector. Review verified local
copies before any manual cleanup, preserving the newest state artifact.

GitHub scheduled runs can be delayed or dropped, and schedules in public
repositories can be disabled after 60 days without repository activity. Inspect
the Actions page periodically and review failed runs and encrypted coverage
audits. Do not assume a schedule guarantees zero missing news.

Existing local RSS and other-provider jobs can continue. Avoid separately making
large NewsAPI backfill runs against the same key; the cloud counter cannot see
requests made by another client. This deployment does not alter Windows tasks.
